## 2025-02-14 - Fix case-sensitive blocklist bypass in resolve_safe_path
**Vulnerability:** The `BLOCKED_FILE_PATTERNS` check in `botex/security.py` used a case-sensitive `fnmatch.fnmatch()` call against the unmodified path segment. This allowed agents to bypass the blocklist on case-insensitive file systems (like macOS APFS, Windows, or FAT32 mounts on Linux) by simply changing the case of the filename (e.g., requesting `.ENV` instead of `.env`), granting access to protected secret files.
**Learning:** `fnmatch.fnmatch()` behavior is platform-dependent and on POSIX systems (Linux/macOS) it performs case-sensitive matching by default, even if the underlying filesystem is case-insensitive. Security blocklists must manually enforce case-insensitive normalization before comparing inputs against blocked patterns.
**Prevention:** Always normalize the case of user-provided file segments (`segment.lower()`) and patterns (`pattern.lower()`) before performing string equality or `fnmatch` operations in security boundaries that span multiple operating systems or file systems.
